# Review batch — items 1–4

Source-of-truth files live here. Everything else (island pages, compare pages,
sitemap, credits) is regenerated by the normal build chain.

## Apply

```
python3 tools/review/01_privacy.py        # privacy page corrections (EN + EL)
python3 tools/review/gen_why_score.py     # seed why_score.json (skips islands already in it)
python3 tools/review/02_render.py         # fold why_score + provenance into islands/*.json, patch script.js / shells / CSS
python3 tools/review/03_copy.py           # trim the repeated anti-SEO framing, rewrite the festivals card
python3 tools/review/04_prerender.py      # emit both signals into the #seo-fallback
python3 tools/review/05_apply_visited.py  # fold visited.json into islands/*.json
```

Then the usual chain:

```
for f in build_costs build_trip_cost og prerender build_itineraries build_compare_pages \
         build_festival_extras build_festivals build_match_page build_collections; do
  python3 tools/$f.py || echo "FAIL $f"
done
```

All six scripts are idempotent — re-running changes nothing.

## What you edit by hand

- **`why_score.json`** — one sentence per island, EN + EL. Generated from the
  five component scores; edit any line freely, `gen_why_score.py` will not
  overwrite an island already present (use `--force` to regenerate all).
- **`tools/review/visited.json`** — the islands you have actually been to, as
  `"YYYY-MM"`. Everything left `null` renders exactly as the site does today;
  absence never reads as "not visited".
